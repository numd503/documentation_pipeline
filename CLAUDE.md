# CLAUDE.md

Указания для работы над этим репозиторием. Общее описание проекта — в [`README.md`](README.md).

## Что здесь происходит

Реализуется `docpipe` — шаг 1 пайплайна документации: **детерминированное** построение
дерева документации по исходникам .NET. Работа ведётся по плану, а не свободно.

Три документа задают процесс, и их нужно держать в актуальном состоянии:

| Документ | Роль |
|---|---|
| `docs/parser-implementation-plan.md` | 24 задачи с точными критериями приёмки. Источник истины о том, что делать. |
| `docs/implementation-log.md` | Журнал: что сделано, что проверено, где план разошёлся с реальностью. Обновляется после **каждой** задачи. |
| `docs/parser-architecture.md` | Почему принято то или иное решение. Читать перед спором с планом. |

**Порядок работы над задачей:** прочитать её раздел в плане → реализовать → прогнать её
команду проверки → обновить журнал (включая трудности и отклонения) → при расхождении
плана с реальностью **править план**, а не молча обходить.

Реализовывать план будет более слабый агент в другой среде. Поэтому каждая найденная
ловушка должна попадать в план с объяснением, иначе он наступит на неё снова.

## Команды

```bash
uv sync                      # окружение (venv 3.12, uv.lock зафиксирован)
uv run pytest -q             # тесты
uv run docpipe version
uv run docpipe schema --out schema/doc-tree.schema.json

# полная проверка перед коммитом
uv run ruff check . && uv run ruff format --check . && uv run mypy docpipe && uv run pytest -q
```

## Жёсткие правила

**Детерминизм — не пожелание, а проверяемое свойство.** Один и тот же вход обязан давать
байт-в-байт одинаковый выход.

- Любой список в выводе — через явный `sorted()` с явным `key`.
- Порядок обхода ФС **никогда** не используется как источник порядка.
- В `doc-tree.json` не должно быть ни одного недетерминированного поля: ни времени,
  ни хоста, ни абсолютных путей. Всё это идёт в сидкар `doc-tree.run.json`.
- Пути — репо-относительные, POSIX-разделители, даже на Windows.
- Разрешение коллизий — по хэшу ключа, никогда по порядку вставки.

**FQN — не уникальный ключ.** Проверено на ABP: 255 коллизий на 9075 объявлений.
Ключ символа — `модуль + FQN + арность дженерика`, и даже он оставляет остаток
(файлы, не компилируемые вместе, — `Platforms/iOS/` против `Platforms/MacCatalyst/`).
Хэш-суффикс от FQN не разводит ничего там, где FQN совпадает.

**`signature_hash` не включает номера строк и пути.** Иначе переформатирование файла
заставит агента на шаге 3 перегенерировать документ впустую, и вся экономия от
инкрементальности пропадёт.

**Тесты самодостаточны.** `examples/` в репозиторий не входит — опираться на него в тестах
нельзя. Реальные конструкции воспроизводятся в `tests/fixtures/` или в `tmp_path`.

## Ловушки, проверенные на реальном коде

Каждая из них однажды прошла бы все критерии приёмки и сломалась бы в проде.

**`fnmatch` не понимает `**` как «ноль или больше сегментов».** `**/obj/**` не ловит
`obj/x.cs` в корне, `**/*.g.cs` не ловит `Foo.g.cs` там же. Использовать
`discovery.matches_glob`, а не `fnmatch` напрямую.

**Базовые типы бывают многострочными:**
`class X : EndpointBaseAsync\n  .WithRequest<A>\n  .WithActionResult<B>`. Нормализуются
двумя шагами (`\s+` → ` `, затем `\s*\.\s*` → `.`) в `parser.normalize_type_text`.
Без второго шага остаётся `X .WithRequest<A>` — не канонический C#.

**Модификаторы и атрибуты — потомки узла объявления, а XML-doc — предшествующие соседи.**
Асимметрия неочевидная и ловит на ней всех.

**Директивы препроцессора — самая злая находка ABP:**
- `#if` — **контейнер**: члены под ним не являются прямыми детьми `declaration_list`.
  Реализация, перебирающая прямых детей тела, потеряет их молча;
- `#region` — плоский маркер, не контейнер. Асимметрия неочевидная;
- `#if` **внутри выражения** рвёт разбор. Мест много: аргументы атрибута, fluent-цепочка,
  модификатор объявления, базовый список, шаблон в pattern matching. Атрибут —
  потомок объявления, поэтому вместе с ним ломается и объявление: остаток файла
  переразбирается как top-level statements, и тип исчезает из вывода целиком.
  Обойти нельзя. Единственный признак — `parse_errors > 0` при пустом списке объявлений;
  ловить это обязан `validate` (T20). Фикстура: `WildSolution/…/Modules/ConditionalModule.cs`.

**`.csproj` и решения в реальных проектах:**
- сохранены с BOM — читать байтами, `read_text(encoding="utf-8")` уронит `ET.fromstring`
  (в ABP с BOM и 72 % файлов `.cs`);
- обычно **не объявляют** `TargetFramework` (в eShopOnWeb — 0 из 10), он приходит из
  `Directory.Build.props` / `Directory.Packages.props` выше по дереву;
- проекты legacy-формата объявляют `xmlns` — сравнивать только по локальному имени тега;
- `<TargetFrameworks>` может содержать неразвёрнутое `$(TargetFrameworks)` — отбрасывать;
- имена проектов **не уникальны** (в ABP 39 повторов), поэтому `id` модуля и
  `project_references` строятся от путей, а не от имён;
- решение может быть в формате `.slnx` (XML, VS 17.10+): в ABP их 30, в OpenTelemetry 1,
  и в обоих `.sln` — ноль; semantic-kernel держит оба формата сразу;
- `Include` в `ProjectReference` часто собран из подстановок MSBuild (`$(RepoRoot)\…`).
  Склеивать такое с каталогом проекта **нельзя** — получится выдуманный путь, который
  выглядит настоящим. Дорезолвливает `csproj.resolve_references` по имени файла.

**`Program.cs` в современном .NET — top-level statements**, без класса и метода.
Поиск DI-регистраций обязан идти по всему дереву файла, а не внутри `method_declaration`.

**Версия API tree-sitter — 0.25+.** `Query(LANG, src)` + `QueryCursor(q).captures(node)`,
возвращающий `dict[str, list[Node]]`. Старые формы `LANG.query(...)` и
`query.captures() -> list[tuple]` не работают.

## Инварианты фикстур

`tests/fixtures/SampleSolution/` — канонические случаи. **На точные количества в нём
завязаны критерии приёмки T04–T20** (11 файлов после исключений, 10 символов, 6 узлов).
Расширять эту фикстуру нельзя: новые случаи идут в `WildSolution`.

`tests/fixtures/WildSolution/` — конструкции, пойманные в реальных репозиториях.

Два инварианта, которые легко нарушить:

1. **Не добавлять `obj/` и `bin/` в `.gitignore`.** В `SampleSolution` есть файл под `obj/`,
   на котором проверяются правила исключения. Стандартный .NET-шаблон `.gitignore` его
   выкинет, и тесты T04/T14 продолжат проходить, ничего не проверяя.
2. **Тесты фикстур проверяют наличие конструкций, а не только файлов.** Иначе «упрощение»
   фикстуры оставит тесты зелёными и бессмысленными.

## Конвенции кода

- Комментарии, docstring и сообщения об ошибках — по-русски; идентификаторы — по-английски.
- Комментарий объясняет **почему**, а не что. «Читаем байтами, потому что BOM уронит
  `ET.fromstring`» — полезно; «читаем файл» — нет.
- Модели — `pydantic`, `frozen=True`, `extra="forbid"`.
- `ruff` настроен с `line-length = 100` и исключает `docs/` и `examples/`: в плане лежат
  намеренно компактные псевдо-сигнатуры в python-блоках, `ruff format` их ломает.
- `mypy` в режиме `strict`.
