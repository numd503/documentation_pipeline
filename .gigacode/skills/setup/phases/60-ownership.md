# Фаза 60: владение и домены

## Цель

У каждого документа есть команда-владелец — очередь `worklist --team`
делится по командам; домены, если человек их назвал, сгруппировали модули.
Имена команд и доменов — ключи, их называет человек.

## Инструменты

- `setup_status` — `owners.not_configured`, `owners.unowned`, кластер `module`;
- `setup_docs` (`docpipe docs status`) — команда у каждого документа;
- `docpipe recon` — блок `archaeology` (каталоги одного автора; `setup_recon`
  его не отдаёт): подсказка, а не ответ;
- линт владения — только командой, двойника-инструмента нет:

```bash
cd ПРОДУКТ && docpipe scan --root . --config CFG
cd ПРОДУКТ && docpipe docs owners МАНИФЕСТ --config CFG --lint --format json
cd ПРОДУКТ && docpipe docs owners МАНИФЕСТ --config CFG --explain ПУТЬ_ДОКУМЕНТА
```

МАНИФЕСТ — `out` из ответа `setup_config_check`; `scan` пересобирает его
по текущей настройке.

## Шаги

1. **Владение не настроено** (`owners.not_configured`: ключ `ownership`
   не задан) или настроено пусто (нейтральный набор: `ownership.yaml`
   без команд — все документы в `owners.unowned`). Вопрос «Владение»:
   по модулям или одна команда на всё. Команды (`teams[].id` — то, что
   пишут в `--team`, и `teams[].title`) называет человек.
2. **Слой 10** — по правилу на команду, `priority: 10`, условие
   `rules[].when.module_glob` по каталогам, которые назвал человек.
   Правило пишешь ты, команду — из ответа.
3. **Линт** — `docpipe docs owners … --lint`: `dead-rule` (правило ни на
   что не легло — опечатка в глобе), `priority-tie` (два правила одного
   приоритета на одном узле), `split-type` (части `partial`-типа у разных
   команд). Слой 50 и выше — только там, где линт показал смешение
   команд внутри модуля, по `rules[].when.path_glob`.
4. **Ничьи после слоя** (`owners.unowned`) — кластер `module`; модуль
   у объявленной команды — дописываешь глоб сам, новая команда —
   вопрос «Владелец» по разделу `owners.unowned`.
5. **Домены** — кода находки нет, вопроса нет. Скажи вслух: «домен
   сейчас — имя модуля»; кандидаты — `projects.dotnet_projects` разведки.
   `domains` в `docpipe.yaml`: глоб `.csproj` → имя домена. Имя — ключ
   (`{{ domain }}` в скелетах, предикат владения `rules[].when.domain`),
   правка — только по слову человека.

## Контрольная точка

- `setup_status` — нет `owners.not_configured` и `owners.unowned`;
- линт владения — без `dead-rule` и `priority-tie`;
- `setup_docs` — у каждого документа команда не пуста.

## Ловушки

- **Владелец определяется по узлу, а не по модулю**: в общем `.csproj`
  бывает код нескольких команд — для этого слои выше 10.
- **Имена проектов не уникальны** (ABP — 39 повторов): `rules[].when.module`
  накроет оба одноимённых; по пути — `rules[].when.module_glob`.
- **Команда правила обязана быть в `teams`** — иначе отказ загрузки;
  `--team` с неизвестным именем — тоже отказ, а не пустая выборка.
- **Смена домена молча выводит узлы из правила по `domain`**, а у фронта
  домена нет вовсе: правило по домену фронт не накроет.
- **Переименование вида** в правилах классификации — `dead-rule` у правил
  по `rules[].when.kind`.
- **`domains`: побеждает первый совпавший глоб в порядке ключей**;
  опечатка — доменом молча станет имя модуля.
- **Только положительные правила**: более специфичное — бо́льшим
  приоритетом, а не исключением из общего.

## Правка файлов

`ownership.yaml` (ключ `ownership` в `docpipe.yaml`; в нейтральном наборе
назван, файл — заготовка с `teams: []` и `rules: []`): замени пустые
списки записями. `domains` — в `docpipe.yaml`, раскомментируй ключ.

```yaml
# file: ownership.yaml
version: "1"
ownership_version: "1"
teams:
  - id: "<команда от человека>"
    title: "<название команды>"
rules:
  - id: "<команда от человека>.modules"
    team: "<команда от человека>"
    priority: 10
    when:
      module_glob: ["src/Pricing/**"]
```

```yaml
# file: docpipe.yaml
domains:
  "src/Pricing/**": "<домен от человека>"
```
