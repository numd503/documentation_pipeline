# Фаза 50: раскладка и документы

## Цель

Где лежат документы, решено окончательно — до первого `materialize`;
обход документов видит всё дерево и не заходит в каталог настройки;
у каждого вида есть скелет; план шага 2 собирается без ошибок, а сирот,
испорченных и невидимых документов нет.

## Инструменты

- `setup_docs` (`docpipe docs status`) — документы: `doc_path`, `status`,
  `file_action`; аргумент `status` — только с этим статусом;
- `setup_docs_explain` (`docpipe docs explain`) — один документ: какой
  фильтр сработал, что перепишет прогон;
- `setup_status` — `docs.orphan`, `docs.broken`, `docs.shadowed`,
  `docs.unavailable`;
- `setup_config_check` — `templates`, `docs_root`, `docs_scan_exclude`.

## Шаги

1. **Раскладка — вопрос человеку, один раз и до записи документов.**
   Покажи два-три `doc_path` из `setup_docs` и спроси «Раскладка»: где
   дерево документов (`docs_root`), каталог технической документации
   (`modules_dir`, фронт — `web.modules_dir`), порядок сегментов
   (`doc_layout`: `kind-first` — `controllers/<модуль>/…`, `module-first` —
   `<модуль>/controllers/…`). Умолчания — `docs`, `modules`, `kind-first`.
2. **`docs_scan_exclude`** накрывает КАТАЛОГ (в его `templates/examples/`
   лежат образцы с настоящим front matter) и не накрывает дерево
   документов. Сверь шаблоны с `doc_path` из `setup_docs`: ни один
   `doc_path` не должен под них попадать.
3. **Скелеты.** На каждое значение `template` из `rules.yaml` — файл
   `КАТАЛОГ/templates/<имя>.md`. Нет скелета — документ получит
   `default.md`, без ошибки. Новый вид (фазы 10, 20) — новый скелет:
   скопируй ближайший и поправь заголовки разделов. Подсказки в скелете —
   только HTML-комментарии `<!-- … -->`: обычный текст делает раздел
   «написанным», и агент шага 3 его пропустит.
4. **План шага 2** — `setup_status`: `docs.unavailable` с текстом ошибки —
   нет скелетов, битый `ownership.yaml`, коллизия путей. Чинишь по тексту
   (`docs/setup-interview.md`, раздел `docs.unavailable`).
5. **Состояние документов** — `setup_docs`:
   - `docs.orphan` — документ без узла: вопрос «Сирота» (перенос
     `docpipe docs adopt`, удаление, вернуть имя раздела или раскладку).
     Перенос и удаление — действие человека или по его слову;
   - `docs.broken` — front matter испорчен: документ правит человек
     (или ты по его слову, показав разницу), `--force` не лечит;
   - `docs.shadowed` — файл на пути узла есть, обход его не видит:
     `setup_docs_explain` называет фильтр. `docs_scan_exclude` — сужаешь
     сам; BOM, права, симлинк — человеку.
6. **`materialize` в настройку не входит.** Документы создаются после
   коммита настройки, по слову человека и сначала с `--dry-run`:
   `docpipe materialize МАНИФЕСТ --root . --config CFG --dry-run`, где
   МАНИФЕСТ — `out` из ответа `config check`, собранный `docpipe scan`.

## Контрольная точка

- `setup_config_check` — без `input-missing` и `input-shadowed` у `templates`;
- `setup_status` — нет `docs.orphan`, `docs.broken`, `docs.shadowed`,
  `docs.unavailable`;
- `setup_docs` — все `doc_path` под префиксом `docs_root`/`modules_dir`,
  который назвал человек; статусы до первой записи — `missing` с действием
  `create`.

## Ловушки

- **Раскладка замерзает в манифесте.** `doc_path` собирается на шаге 1
  из `docs_root` + `modules_dir` + `doc_layout`; смена после `materialize`
  даёт вечный `missing` и перезапись при каждом прогоне. Менять — только
  с полной пересборкой и переносом документов (`docs adopt`).
- **Раскладка на коллизии не влияет**: `kind-first` и `module-first` —
  перестановка одной тройки; споры о «безопасной раскладке» бесполезны.
- **`docs_scan_exclude` умеет накрыть само дерево документов**: при
  `docs_root` под КАТАЛОГ шаблон `КАТАЛОГ/**` спрячет все документы.
- **`missing` — «файла нет», а не «обход не вернул»**: документ с BOM,
  без `docpipe.schema` или за симлинком — это `docs.shadowed`, и
  `materialize --force` его не перезапишет намеренно.
- **Статус и действие — разные вещи**: `current` с действием `update`
  законен — сменился владелец или домен.
- **Префикс — пара `docs_root` + `modules_dir`**, а не один путь:
  раздельно их не «чинят».
- **Скелет с текстом-подсказкой вместо HTML-комментария** — самая дорогая
  ошибка шага 2: раздел сочтут написанным.

## Правка файлов

`docpipe.yaml`: ключи раскладки в нейтральном наборе закомментированы
умолчаниями — раскомментируй, только если человек выбрал другое.
`docs_scan_exclude` уже содержит КАТАЛОГ — добавляй рядом, не заменяй.
Скелеты — файлы в `КАТАЛОГ/templates/`, документы в дереве — не твои.

```yaml
# file: docpipe.yaml
docs_root: "docs"
modules_dir: "modules"
doc_layout: "kind-first"
docs_scan_exclude:
  - "docs/docpipe/**"
  - "docs/archive/**"
web:
  modules_dir: "frontend"
```
