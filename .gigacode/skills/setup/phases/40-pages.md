# Фаза 40: страницы и разделы

## Цель

У каждой страницы фронта есть якорь — собранный маршрут; каркасы без
своего экрана сняты; функциональные единицы без маршрута, которые
открываются с нескольких экранов, объявлены разделами; ни одно правило
`pages.yaml` не протухло.

## Инструменты

- `setup_pages` (`docpipe web pages`) — страницы, записи маршрута
  с `source` и `table`, заметки: несобранный маршрут, пустой маршрут,
  нет признаков функционала; аргумент `note` — только с этой заметкой;
- `setup_candidates` (`docpipe setup candidates`), вид `features`;
- `setup_status` — находки `pages.*`, кластер `module` (`kind` у протухших);
- `setup_explain` (`docpipe setup explain`) — `pages`, `page_overrides` файла.

## Шаги

1. **Список страниц** — `setup_pages`. Страниц ноль при таблице роутов
   в коде — дело в разборе роутов или в виде `component` (фаза 20), а не
   в `pages.yaml`. Кода находки у списка нет — вопроса нет, скажи вслух:
   страниц N, компонентов без маршрута M (`counts.components_without_route`),
   три-пять маршрутов из `setup_pages`. Назвал человек экран, которого
   нет, — это его слово: запись `add` по его ответу.
2. **Якорь не поставить** (`pages.unanchorable`): ни один маршрут страницы
   не собран. Вопрос «Якорь»: маршрут — запись `add`; «не страница» —
   `remove` с причиной человека.
3. **Часть маршрутов не собрана** (`pages.route_unresolved`): маршрут
   собран выражением (`archiveSegment`). Путь из кода предлагаешь ты —
   это утверждение о приложении, его подтверждает человек вопросом
   «Маршрут»; ответ — `add` с маршрутом и FQN компонента из `setup_pages`.
4. **Каркас** (`pages.layout`): страница без членов на пустом маршруте или
   без вызовов и стейта. Открой шаблон компонента (`<router-outlet>`),
   вопрос «Layout?»: снять везде — `remove` по `component`, на одном
   маршруте — `remove` по `route`. Ответ «это страница» записи не имеет:
   находка остаётся, скажи вслух.
5. **Разделы** — `setup_candidates`, `kind: features`. Кандидат — каталог,
   где общие для нескольких страниц узлы двух видов и больше (стейт и
   сервисы). Кандидат — не находка: вопроса нет, назови кандидатов списком
   вслух. **Имя раздела называет человек**, если захочет: оно становится
   `node_id` и ключом якоря, переименование потом осиротит документ.
   Промолчал — раздела нет. Кандидат на пол-приложения (`src/app`) —
   не раздел.
6. **Протухшие правила** (`pages.stale_overrides`):
   - `add-missed` после переноса файла (FQN сменился, класс тот же,
     `git log --follow` это показывает) — переносишь FQN сам;
   - `add-redundant` — маршрут теперь собирается сам: удаляешь запись сам
     и показываешь, что страница на месте;
   - `remove-missed` — снятие **не переносишь** сам: на другой класс оно
     молча применило бы чужое «не документируем». Вопрос «pages.yaml».

## Контрольная точка

- `setup_status` — нет находок `pages.*`, кроме названных человеку
  пробелов формата;
- `setup_pages` — у каждой страницы маршрут без `?` хотя бы в одной записи;
- `setup_candidates`, `kind: features` — у каждого кандидата, которого
  человек назвал разделом, `declared: true`.

## Ловушки

- **Вид `page` не выдаётся правилом**: страницей компонент делает маршрут
  из таблицы роутов, собранной межфайлово. Почему класс страница —
  `setup_pages` (`source`, `table`), а не `setup_symbols`.
- **Дерево роутов собирается спредом импортированных массивов**: один
  `app.routes.ts` даёт два пути из двадцати шести. Мало страниц — смотри
  `source` записей, а не только корневую таблицу.
- **`() => import('./x').then(m => m.ROUTES)` — две стрелки**: имя таблицы
  берётся не из `then`.
- **«Страница внедрила сервис» и «страница зовёт метод» — разные вещи.**
  Состав страницы — по графу вызовов; список по внедрению — вторая
  величина, разница между ними — мера.
- **Поход за данными через `dispatch(new X())`** → `@Action(X)` → сервис:
  вызовы страницы не видны в конструкторе, `setup_pages` называет такие
  случаи.
- **FQN компонента зависит от пути файла**: перенос файла — `add-missed`.
- **Снятие сильнее добавления**: автоматика → `add` → `remove`.
- **Пустой маршрут — не всегда каркас**: экран входа на `/` с членами —
  страница; его не снимают.
- **Две формы файла**: с телом `pages:` и плоская. `add` рядом с `pages:`,
  а не внутри него, — отказ загрузки; `features` — в одном месте.

## Правка файлов

`pages.yaml` (ключ `web.pages` в `docpipe.yaml`; в нейтральном наборе
файл уже назван и пуст — `add: []`, `remove: []`, `features: []`).
Замени `[]` списком записей. У каждой записи `reason` обязателен: у `add`
по коду — адрес доказательства, у `remove` и раздела — слова человека.
`component` — FQN из `setup_pages`: путь файла без `.ts`, точка, имя класса.

```yaml
# file: pages.yaml
version: "1"
pages:
  add:
    - route: "/models/archive"
      component: "src/app/models/list.component.ListComponent"
      reason: "маршрут собран выражением archiveSegment, src/app/routesPath/models.ts:14"
  remove:
    - route: "/"
      reason: "<слова человека>"
features:
  - name: "<имя от человека>"
    path: "src/app/shared-orders"
    title: "Заказы"
    reason: "<слова человека>"
```
