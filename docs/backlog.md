# Долг и направления

Единый список того, что не сделано, — по цели из [`purpose.md`](../purpose.md)
(ревизия 06.10.2026). Раньше хвосты жили в разделах «Отложено» и «Не входит»
каждого закрытого плана, и увидеть их вместе было нельзя: закрытый план
никто не перечитывает, а пункт в нём числится долгом вечно.

Правило: пункт, закрытый или отменённый, переносится **здесь** в раздел
«Закрыто» с датой и получает запись в журнале. Новый хвост плана сначала попадает сюда, а потом уже
в план. Источник каждого пункта указан, чтобы можно было найти исходные
рассуждения.

## В цели: связи документации

Граф связей документации — направление, плана ещё нет. Что уже есть
и чего не хватает:

| Пункт | Что сделать | Источник |
|---|---|---|
| **Фронт↔бэк в документах** | `web link` считает, какая страница зовёт какой эндпоинт, но в документ это не попадает: в разделе «Данные» страницы маршрут не ссылается на документ контроллера, в документе контроллера нет «кто зовёт». Данные есть — нужна проекция в `materialize`. **Источник решён 06.10 — `web link`**: документация не должна зависеть от движка графа, и в нём есть «почти» совпадения; `graph/web.py` берёт сопоставления у него, а не считает своим точным ключом | ревизия 06.10, `module-review.md` |
| **Распространение устаревания** | сигнал «у зависимости сменился контракт — пересмотри зависящие документы». Сейчас устаревание распространяется только внутри документа страницы (поглощённые узлы) | ревизия 06.10; механизм достижимости — G07 |
| Артефакт графа документации | рёбра «документ ↔ документ» с видом связи, детерминированно. Источники рёбер: зависимости и связи манифеста, состав страниц, `web link`, а из графа кода — связывание по DI (G04), швы через грид (G06), сущности реестра (G05b) | ревизия 06.10 |
| **Правила связей между языками** | связь задаётся правилом в настройке, а не кодом: ключ на стороне A, ключ на стороне B, приведение к общему виду, вид связи. Правила находит и составляет ассистент при настройке (`purpose.md`); `docpipe` применяет их детерминированно и считает связи и концы без пары. Встроенным остаётся только общее для всех (HTTP фронт↔.NET). Сейчас есть отдельные куски: `web.url_rewrite` и `web.registry_calls` (HTTP фронта), записи `seam` в `arch-registry.yaml` (шов поштучно, один литерал), адаптер `python_code` (реестр кодом). Нужен один формат, в котором выражаются все три, — иначе ассистенту нечего составлять | ревизия 06.10 |
| Python↔.NET в документах | первый потребитель правил связей; сейчас шов строится только в графе кода (G16 п. 4); для документов — после Python в дереве | G16, PY11–PY12 |
| Два формата точек входа | `arch-registry.yaml` (R03) и `registries.yaml` + `anchors` (бизнес-слой) описывают одно понятие по-разному; для графа документации нужен один | ревизия 06.10 |

## В цели: настройка с ассистентом

Настройку на репозиторий ведёт агент контура: через скиллы, MCP-инструменты
и интервью с пользователем (`purpose.md`, раздел «Настройка с ассистентом»).
План — [`setup-implementation-plan.md`](setup-implementation-plan.md)
(S01–S32, 07.10.2026); ниже — задачи, из которых он написан. Порядок важен: карта
цепочек нужна всем трём каналам, а интервью без детерминированных находок
превращается в анкету. Аналитика перед планом — разбивка на 25 задач,
решения Р-1…Р-6, молчаливые места и расхождения справочников с кодом —
в [`setup-assistant-analysis.md`](setup-assistant-analysis.md).

| Пункт | Что сделать | Сейчас |
|---|---|---|
| **Карта цепочек настройки** | каждый ключ `docpipe.yaml` и каждый файл настройки (`rules.yaml` по секциям, `ownership.yaml`, `registries.yaml`, `pages.yaml`, `arch-registry.yaml`, шаблоны): кто читает, от какой базы разрешается, чем проверяется, **откуда берётся значение** — из кода, из разведки или только от человека — и что ломается молча при ошибке. Это вход и для скилла, и для вопросов интервью | разбросано по `configuration.md`, ловушкам CLAUDE.md и README «Настройка под конкретный проект» |
| **Скилл настройки** | сценарий для gigacode от «репозиторий вижу впервые» до критерия «настройка закончена»: разведка → черновик `docpipe.yaml` → `config check` → `scan --stats` → правила и отсев → `web scan`/`web pages` → `materialize`/`docs status`. На каждом шаге — контрольная точка командой, а не мнением агента | скилл `recon` доходит до черновика `arch-registry.draft.yaml`; остальное человек делает по README |
| **MCP-инструменты настройки** | детерминированные ответы, которые агент зовёт по ходу: разведка, разрешение путей (`config check`), группы `undecided` с подсказками (`scan --stats`, `symbols`), «почему страница» (`web pages`), сводка `docs status`. Работают **без индекса графа**: настройка идёт раньше сборки | сервер `graph serve` есть; без индекса работают только `docpipe_overview` и `docpipe_why`, остальные требуют собранного индекса; инструментов настройки нет. Решено 07.10: отдельный сервер `docpipe setup serve` (Р-3 аналитики) |
| **Интервью с пользователем** | протокол: какие решения принадлежат только человеку (что документировать и почему нет, домены, владельцы, какие реестры авторитетны, какие каталоги — разделы без маршрута, префиксы прокси); вопрос строится из находки команды («120 типов в `*.Migrations` — документировать?»), ответ ложится в файл настройки с причиной от человека | нет |
| Повторная настройка | вернуться к настройке после изменений в репозитории и спросить **только о новом**: прошлые решения уже лежат в файлах настройки | нет; признаки нового уже считаются (`undecided`, `feature-empty`, `route_unresolved`) |
| Поиск связей между языками | ассистент находит кандидатов в правила связей: литералы, которые встречаются по обе стороны шва, реестры, регистрации; проверяет правило прогоном (сколько связей, сколько концов без пары) и предлагает человеку. Опора — разведка (`recon` уже ищет швы) и пункт «Правила связей между языками» выше | `recon` и скилл предлагают швы в черновик `arch-registry`, поштучно |
| Критерий «настройка закончена» | одной командой: в области нет находки без решения (документируем или нет, с причиной) и нет дефектов; вне области — строкой с числами; остановку решает человек (Р-6 аналитики, 07.10) | проверки есть по отдельности; находки без места для решения — эндпоинт без вызывающего, вызов во внешний адрес |
| Доставка на контур | скилл лежит в git клона (`.gigacode/skills/`), `install.sh` прописывает MCP-сервер в `.gigacode/settings.json` клона — так доставляются `recon` и `graph serve`; расширить на скилл и инструменты настройки (S30 плана) | перенос из `.qwen/` в `.gigacode/` сделан 07.10 (S01 плана) |
