# `arch-registry.yaml`: нормализованный реестр архитектурных элементов

Справочник по формату R03. Зачем он нужен и какие решения за ним стоят —
в [`graph-implementation-plan.md`](graph-implementation-plan.md); здесь —
что лежит в файле и как его заполнить.

## Что это

Один формат для всех репозиториев — **контракт между разведкой и графом**.
Слева от него догадки, ручная работа и подсказки модели; справа —
детерминированная сборка. Всё, что попало в файл, человек прочитал
и закоммитил; всё, что не попало, в граф не входит.

Файл отвечает на один вопрос: **что в этом репозитории объявлено, а не
написано.** Контроллер, видный в коде, сюда не пишут — его найдёт разбор.
Сюда пишут то, чего в коде нет структурно: workflow, диспетчеризуемый
по строке из XML; таблицу, известную по декларации; шов между языками;
роль модуля.

Пустой реестр — **валидное состояние**. На репозитории, где точки входа
объявлены в коде, граф строится и без него.

## Команды

```bash
docpipe arch validate arch-registry.yaml          # проверить целиком
docpipe arch validate черновик.yaml --draft       # проверить черновик скилла
docpipe arch status arch-registry.yaml --root .   # не отстал ли снимок
docpipe arch status … --json                      # то же машине
docpipe arch status … --fail-on-stale             # ненулевой код при отставании
docpipe schema --model arch                       # JSON Schema из моделей
```

Путь берётся из ключа `arch` в `docpipe.yaml`, если не задан аргументом.
Это **вход** инструмента, поэтому он разрешается двумя ступенями: сначала
от текущего каталога, потом от каталога `docpipe.yaml`.

## Как заполнить за пятнадцать минут

1. `python3 tools/recon.py --root . --json recon.json` — разведка;
2. блок 4 отчёта, «чем система заякорена», даёт кандидатов в реестры:
   пару «файл + группа» и примеры идентификаторов с местом объявления;
3. блок 5, «как языки говорят между собой», даёт кандидатов в швы;
4. подтверждённое переносится в `arch-registry.yaml` руками;
5. `docpipe arch validate` — и он же назовёт все ошибки сразу, а не первую.

Пример заполнения на открытом репозитории — `arch-registry.example.yaml`
в корне. Он намеренно снят с чужого репозитория: формат не должен быть
удобен ровно одному.

## Четыре вида записей

| Вид | Что это | Ключ — это |
|---|---|---|
| `entry_point` | то, что **запускают**: workflow, джоб, обработчик события, HTTP-эндпоинт, грид-сервис, страница | то, что обязан знать вызывающий |
| `data` | то, что **трогают**: таблица, представление, процедура | логическое имя (`схема.таблица`) |
| `seam` | шов: маршрут, имя грид-сервиса, имя очереди | литерал, который знают обе стороны |
| `layer` | модуль и его роль | путь модуля |

### Общие поля

| Поле | Обязательно | Что значит |
|---|---|---|
| `kind` | да | вид записи из таблицы выше |
| `key` | да | якорь; см. «Ключи» ниже |
| `name` | нет | человеческое имя. Для данных сюда идёт `DisplayName` — на репозитории с русским глоссарием это единственный источник предметных слов, и он попадёт в поиск |
| `source.file` | **да** | репо-относительный путь к файлу, где факт объявлен |
| `source.record` | нет | адрес внутри файла: XPath, ключ JSON, имя символа |
| `source.hash` | нет | `sha256:…` источника на момент снимка |
| `provenance` | да | `manual`, `skill_confirmed`, `adapter`, `skill_proposed` (только в черновике) |
| `attributes` | нет | пары «строка → строка» для того, чего в схеме нет |
| `note` | нет | заметка человеку |

**Запись без источника не принимается на уровне загрузки.** Причина та же,
по которой в правилах отсева обязателен `reason`: безымянная запись через
месяц неотличима от выдумки, а выдумка в реестре — это уверенно неверное
ребро графа, худший вид ошибки.

### Поля по видам

`entry_point`: `entry_kind` (`workflow`, `job`, `event_handler`,
`http_endpoint`, `grid_service`, `page`, `service`, `cli`, `other`), `impl`
— подсказка на код, `route` и `http_method` — для HTTP, `touches` — ключи
записей `data`, на которых точка входа сидит по декларации.

`impl` — именно подсказка, а не ссылка: связь «запись → узел кода» делает
граф, и её отсутствие не дефект. Корень существует в графе независимо
от того, нашёлся ли под него класс.

`data`: `data_kind` (`table`, `view`, `procedure`, `other`), `table` —
таблица-носитель, когда ключ логический; `fields` — список полей
(`name`, `kind`, `display_name`, `references`); `references` — ключи других
узлов данных.

Вид поля (`kind`) — свободная строка, а не словарь: перечень видов у платформы
заведомо неполон, и потерять поле дороже, чем принять опечатку.

`seam`: `seam_kind` (`http_route`, `grid_service`, `queue`, `topic`, `file`,
`other`), `literal`, `http_method`, `sides` — стороны шва как их называет
репозиторий (языки, модули, проекты).

`layer`: `role` (`host`, `service`, `library`, `frontend`, `tests`,
`generated`, `tooling`, `other`), `path`, `language`.

## Ключи и нормализация

Ключи нормализуются **одним правилом на весь проект** — `docpipe/keys.py`.
Вторая нормализация разошлась бы с первой на первом же частном случае
и разошлась бы молча: записи просто перестали бы находить друг друга.

| Вид | Правило | Пример |
|---|---|---|
| `data` | скобки и кавычки снимаются, регистр сворачивается, схема **не дописывается** | `[dbo].[USER_TASKS]` → `dbo.user_tasks` |
| `seam` с `http_route` | маршрутная нормализация: схема, хост, query, подстановки | `https://h/API/Items/{id}?x=1` → `api/items/{}` |
| `entry_point` с `http_endpoint` | метод и маршрут вместе | `GET` + `/api/Items` → `GET api/items` |
| остальные | регистр и «ё» | `CalcDxExcel` → `calcdxexcel` |

Схема к имени таблицы **не дописывается**: `USER_TASKS` и `dbo.USER_TASKS`
остаются разными ключами. Дописать умолчание заманчиво и неверно —
на репозитории с несколькими схемами это склеит таблицы разных схем в одну.

Один ключ — одна запись, и совпадение считается **после** нормализации.
Одинаковый ключ у записей разных видов законен: шов `api/x` и точка входа
`api/x` — разные вещи.

## Провенанс и граница подтверждения

| Значение | Что означает |
|---|---|
| `manual` | вписал человек |
| `skill_confirmed` | предложил скилл разведки, человек проверил и перенёс |
| `adapter` | читается адаптером при каждой сборке, снимка нет |
| `skill_proposed` | **черновик**: предложено, не подтверждено |

**`skill_proposed` в реестре запрещён и отвергается при загрузке.** Это
структурная реализация правила «недетерминированное входит не в пайплайн,
а в файл, который человек прочитал»: предложение модели становится входом
графа, только пройдя через человека, и «пройдя» видно в данных, а не
в памяти. Черновик проверяется командой `arch validate --draft`.

Ранний признак того, что подтверждение выпало из цикла, — файл, в котором
провенанс `skill_proposed` не сменился ни разу.

## Снимок и адаптер

Два законных способа получить записи, и выбор между ними — решение,
а не деталь.

**Снимок** (`manual`, `skill_confirmed`) — реестр разобран один раз, результат
лежит в файле. Работает для чего угодно, включая формат, который мы видим
впервые. Стареет.

**Адаптер** (`adapter`) — код читает исходный реестр при каждой сборке.
Не стареет, стоит реализации на семейство форматов.

По умолчанию снимок.

### Что показывает `arch status`

| Состояние | Что значит |
|---|---|
| `source_missing` | файла источника нет: переименован, удалён, перенесён |
| `stale` | источник изменился после снимка — запись устарела |
| `no_hash` | хэш не записан (или источник — каталог): устаревание не ловится |
| `live` | адаптер читает источник при каждой сборке |
| `current` | снимок совпадает с источником |

**Существование проверяется до хэша и независимо от него.** Хэш ловит только
случай «источник менялся»; запись, чей файл переименовали или удалили,
осталась бы тихой. Поэтому `source_missing` виден даже у записи без снимка.

Отчёт печатает актуальный хэш строкой, готовой к вставке в `hash:`. Без этого
человек, увидевший «снимок отстал», идёт считать `sha256` руками — а это
ровно та мелкая работа, из-за которой проверку перестают делать.

Красным по умолчанию отчёт не бывает: устаревший снимок — состояние работы,
а не дефект. Порог задаёт вызывающий флагом `--fail-on-stale`.

## Адаптеры (R04)

Адаптер подключается **по имени в конфигурации**, а не ветвлением в ядре.
Ядро не знает ни одного конкретного реестра ни одного конкретного репозитория:
пути, теги и имена атрибутов живут в конфигурации.

```yaml
arch_adapters:
  - id: платформенные-реестры
    adapter: registries
    options:
      spec: registries.yaml
  - id: сервисы-питона
    adapter: python_code
    options:
      path: services/registry.py
      call: register
      entry_kind: service
```

| Адаптер | Что читает | Параметры |
|---|---|---|
| `registries` | декларативные реестры по описанию `registries.yaml`: XML, JSON, переходы по ссылкам | `spec` (обязателен), `kinds` |
| `python_code` | реестр, записанный кодом на Python | `path` (обязателен), `variable`, `call`, `entry_kind` |

Неизвестное имя адаптера и неизвестный параметр — отказ, а не молчание:
пропущенный адаптер даёт реестр без части записей, а такой реестр внешне
неотличим от репозитория, где этих точек входа нет вовсе.

### `registries`: вид записи → вид записи графа

Отображение задаётся параметром `kinds` и складывается с умолчаниями
(`grid_service` → `entry_point:grid_service`, `list` → `data:table`,
`list_field` → `field`, `kafka_topic` → `seam:topic` и так далее). Вид,
которому не назначен вид графа, **называется вслух**: записи пропускаются,
и об этом печатается строка.

Две добавки к ключу, и обе не украшение:

- **версия входит в ключ**, если у записи есть поле `version`: `Sample@2`.
  Один процесс живёт в репозитории в нескольких версиях сразу, и ключ
  без версии склеил бы их — вторая пропала бы как дубль;
- **родитель входит в ключ вложенной записи**: `UserTasks:ItemAdded`.
  Одно и то же `ItemAdded` есть у десятка списков, само по себе оно не адрес.

У одного якоря бывает несколько реализаций (на паре «список + EventType»
сидят и аудит, и запуск процесса), поэтому `impl` — список. В файле пишется
и строкой, и списком.

### `python_code`: реестр, записанный кодом

**Модуль разбирается статически и никогда не импортируется.** Импорт чужого
файла ради «посмотреть, что зарегистрировалось» — это выполнение произвольного
кода репозитория при разведке. Плата принята и названа: динамическая
регистрация (цикл по каталогу, сборка имени из кусков) сюда не попадёт.

Три формы, и все три встречаются в одном файле:

```python
SERVICES = {"forecast": ForecastHandler}       # словарь
ROUTES = [("/forecast", ForecastHandler)]      # список пар
register("forecast", ForecastHandler)          # вызов регистрации
```

### Снимок с адаптера

```bash
docpipe arch records --root .                     # что вообще входит в реестр
docpipe arch snapshot --out arch-registry.yaml    # живое чтение → файл
```

Снимок пишется **с хэшами источников**, поэтому `arch status` начинает ловить
его устаревание сразу, без дописывания сорока строк руками.

Снимок и адаптер на одном источнике совпадают запись в запись — это тест,
и он единственный, что удерживает два пути честными.

При совпадении ключей **выигрывает запись снимка**: она прошла через человека
(Р10). Совпадение печатается — молча выброшенная запись через месяц
неотличима от потерянной. Дубль внутри адаптеров — отдельная категория:
это другая находка, и чинят её в другом месте.

## Версия формата

`version: "1"`. Несовпадение — отказ с указанием, что делать, а не попытка
прочитать: файл другой версии, прочитанный как этот, даёт записи, которых
автор не писал.
