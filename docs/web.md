# Шаг `web`: что на выходе и как им пользоваться

Справочник по выходу шага `web`. Обоснования решений — в
[`frontend-analysis.md`](frontend-analysis.md) и
[`frontend-implementation-plan.md`](frontend-implementation-plan.md), факты
о боевом репозитории — в [`findings-cashflow-frontend.md`](findings-cashflow-frontend.md).
Здесь — что лежит в файлах и какими командами это получается.

## Три файла

```
artifacts/doc-tree.web.json       манифест фронта — та же схема, что у шага 1
artifacts/doc-tree.web.run.json   сидкар: время, хост, версии, счётчики
artifacts/web-link.json           отчёт связи фронт↔бэк
```

Манифест **отдельный**, схема **общая**. `materialize`, `docs status`
и бизнес-слой работают от `Manifest` и про язык не знают, поэтому шаг `web`
не меняет ни байта в `doc-tree.json` и не удваивает время `scan`.

Различает манифесты поле `modules[].lang`: `"cs"` либо `"ts"`.

## Команды

```bash
# разбор фронта
uv run docpipe web scan --root . --out artifacts/doc-tree.web.json

# настройка набора правил: счётчики и срезы, ничего не пишет
uv run docpipe web scan --root . --stats

# связь двух манифестов
uv run docpipe web link artifacts/doc-tree.json artifacts/doc-tree.web.json \
    --out artifacts/web-link.json

# документы фронта — той же машиной, что и .NET
uv run docpipe materialize artifacts/doc-tree.web.json --root .
uv run docpipe docs status artifacts/doc-tree.web.json --root .
```

Полный прогон на тестовой фикстуре:

```bash
uv run docpipe web scan --root tests/fixtures/WebWorkspace --out /tmp/web.json
uv run docpipe scan --root tests/fixtures/WildSolution --out /tmp/net.json
uv run docpipe web link /tmp/net.json /tmp/web.json --out /tmp/link.json
uv run docpipe materialize /tmp/web.json --root /tmp/webdocs
uv run docpipe docs status /tmp/web.json --root /tmp/webdocs
```

## Что такое модуль фронта

Модуль объявляется одним из четырёх способов, и правила применяются **по месту**,
а не глобально: `angular.json` в корне не отменяет nx-проекта в соседнем каталоге.

| Форма | Что даёт модуль | Граница |
|---|---|---|
| `angular.json` | каждый элемент `projects` | `sourceRoot`, при его отсутствии `root` |
| `nx.json` + `apps/*/project.json` | каждый `project.json` | каталог самого `project.json` |
| `package.json` вне корня | сам каталог | каталог `package.json` |
| ничего из перечисленного | репозиторий целиком | корень |

**Ключ модуля — каталог-граница, а не файл объявления.** Один многопроектный
`angular.json` объявляет несколько модулей, и ключ по файлу склеил бы их в один
вместе с символами: ключ модуля входит в ключ символа.

Файл принадлежит модулю с самой длинной подходящей границей.

## Узел манифеста

Всё как на шаге 1, плюс два поля:

```jsonc
{
  "id": "type:src#src/app/routes/models/quiz/quiz.component.QuizComponent`0",
  "kind": "page",
  "module": "tr-p",
  "routes": [
    { "path": "models/loader/quiz", "component": "…QuizComponent", "route_unresolved": false }
  ],
  "web_calls": [
    { "file": "src/app/shared/services/items.service.ts", "line": 31,
      "key": { "http_method": "GET", "route": "api/items", "discriminator": "dictionaries" },
      "confidence": "high", "via_action": null }
  ]
}
```

- **`fqn` строится от пути файла**, а не от каталога: в TypeScript единица
  изоляции — файл, и два файла одного каталога законно объявляют одноимённый
  `Helper`;
- **`namespace` — каталог файла.** Пространств имён в языке нет; по этому полю
  матчатся правила `namespace_regex`;
- **вызовы лежат на узле того файла, где записаны.** Связь строит сервис,
  а не страница;
- **шаблон `.html` входит в `sources` и в `impl_hash`**, стили `.scss` — нет.

## Виды

Девять видов заводятся правилами `rules/web.yaml`, два — фактами:

| Вид | Чем определяется |
|---|---|
| `component`, `state`, `ng-module`, `pipe`, `directive` | декоратор |
| `interceptor`, `guard` | базовый тип либо суффикс имени |
| `service` | `@Injectable` либо суффикс `Service` |
| `action`, `routes`, `dto` | путь и вид объявления |
| **`page`** | компонент, до которого можно дойти по таблице роутов |
| **`api-service`** | сервис, который делает HTTP-вызовы |

Последние два — повышения: их выдаёт не правило, а факт. Таблица роутов
собирается межфайлово, вызовы разбираются отдельно, и в символе нет ни того,
ни другого. `matched_rules` при повышении не меняется — там записано,
что сработало.

## Отчёт связи

```
Вызовов фронта: 15, эндпоинтов бэкенда: 10.

      6  связь найдена точно
      3  почти совпало: ключи различаются только числом {}
      6  вызов без эндпоинта
      3  эндпоинт без вызывающего
      1  ОДИН КЛЮЧ У ДВУХ УЗЛОВ БЭКЕНДА
```

| Категория | Дефект? |
|---|---|
| связь найдена точно | — |
| почти совпало | нет, инвентарь: одна сторона знает про параметр, вторая нет |
| эндпоинт без вызывающего | нет: его может звать другая система или мобильный клиент |
| вызов без эндпоинта | нет: часть бэка на конвенциональной маршрутизации |
| один ключ у двух узлов бэкенда | **да**: приложение с такой парой не выберет действие |

**Находка не меняет кода возврата**, пока не названа в `--fail-on`, — включая
коллизию. Линт, красный с первого дня, выключат на второй.

Отдельно отчёт печатает:

- **контроллеры с конвенциональной маршрутизацией** — их URL задан
  в `MapControllerRoute`, а не атрибутами, и вызовы к ним честно попадают
  в «вызов без эндпоинта»;
- **модули фронта без записи в `web.url_rewrite`** — пустое правило и отсутствие
  правила разные вещи: первое значит «проверено, преобразования нет».

```bash
uv run docpipe web link A.json B.json --fail-on duplicate_endpoints
```

Известные категории: `linked`, `almost`, `calls_without_endpoint`,
`endpoints_without_caller`, `duplicate_endpoints`. Опечатка отвергается кодом 2:
незнакомое имя означало бы молча выключенную проверку.

## Ключ связи

Пара `(HTTP-метод, маршрут)`, нормализованная общей функцией `docpipe/route.py`.
Шесть шагов в фиксированном порядке:

1. отбросить схему и хост;
2. отбросить query и фрагмент — **разделитель ищется вне подстановки**, иначе
   шаблон `{id?}` обрезается по своему же вопросительному знаку;
3. применить преобразование префикса модуля (`web.url_rewrite`);
4. заменить подстановки на `{}`: `${id}`, `{id:guid}`, `{id?}`, `{*rest}`, `:id`;
5. схлопнуть `//`, снять ведущий и замыкающий `/`;
6. привести к нижнему регистру.

**Различитель в сопоставление не входит.** `api/items/query` — один эндпоинт
платформы для всех имён списков; `listInnerName` отвечает на вопрос «зачем
звали», а не «куда». Два обращения с разными именами дают две связи с одним
эндпоинтом.

## Что шаг не делает

| Не делает | Почему |
|---|---|
| не разбирает `.html` как язык | отдельная грамматика; шаблон участвует хэшем, и этого хватает для статусов |
| не выводит логику интерцепторов | это интерпретатор TypeScript; преобразование задаётся `web.url_rewrite` |
| не собирает цепочку NGXS | `dispatch(new X(…))` не разбирается, `WebCall.via_action` всегда пуст |
| не поддерживает `this.http.request(method, url)` | первый аргумент там не URL, и обработка «через раз» дала бы маршрут `get` |
| не параллелит разбор | 1301 файл разбирается за 1,4 с; пул процессов стоил бы дороже |
