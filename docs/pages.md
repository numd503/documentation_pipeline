# Страница как единица документации

Справочник по задачам P01–P13: что такое страница, как ею управлять и что
попадает в её документ. Обоснования решений — в
[`pages-implementation-plan.md`](pages-implementation-plan.md).

## Что такое страница

Класс с `@Component`, до которого можно дойти по таблице роутов. Вид `page` —
единственный, который **не выдаётся правилом**: правило говорит «компонент»,
а страницей его делает повышение по таблице роутов, собранной межфайлово.

Проверить это можно командой:

```bash
docpipe web pages artifacts/doc-tree.web.json [--depth 2] [--not-pages]
                  [--route ПОДСТРОКА] [--module ПОДСТРОКА] [--format text|json|csv]
```

```
/models/loader/quiz   QuizComponent   [tr-p]
  почему страница  web.component -> component, затем повышение по таблице роутов (1)
  маршруты         /models/loader/quiz   <- src/app/routesPath/models.ts : modelsPath
  документ         docs/modules/pages/tr-p/quiz-component.md
  состав           членов 4, внешний шаблон нет
  зовёт            ItemsService (api-service, шаг 1): dictionaries
  эндпоинтов       2 зовёт, 2 достижимо по внедрению
                   GET /api/items   <- через ItemsService.dictionaries, шаг 1
```

## Две величины эндпоинтов, и почему их две

- **«зовёт»** — эндпоинты, до которых страница доходит **по вызовам**:
  член страницы зовёт член сервиса, в теле которого записан вызов;
- **«достижимо по внедрению»** — сколько их было бы, считай мы по внедрённым
  сервисам.

Разница не дефект, а мера. На боевом модуле она была разительной: у
`ForecastComponent` 13 внедрённых сервисов давали 51 эндпоинт, а 43 эндпоинта
из 61 приезжали ровно на четыре страницы разом — сервис на тридцать методов
зовут ради двух.

Путь виден у каждой строки: `<- через ModelService.byId, шаг 1`. Если до цели
дошли диспатчем, называется и тип экшена — `диспатч [Inner Debt] Load`.

**Чего разбор не видит:** вызовы из шаблона. `(click)="save()"` и
`service.ready$ | async` живут в `.html`, грамматика Angular-шаблонов в дерево
не входит. Отчёт говорит об этом словами там, где вызовов не нашлось.

## Ручной состав: `pages.yaml`

Обход находит страницы по таблице роутов, но таблица знает не всё. Полный
пример — [`pages.example.yaml`](../pages.example.yaml).

```yaml
version: "1"
pages:
  add:
    - route: "/models/list"
      component: "src/app/models/view/view.component.ViewComponent"
      reason: "Страница платформы: данные приходят из грида, маршрут не объявлен"
  remove:
    - route: "/"
      reason: "Layout с router-outlet, собственного экрана нет"
```

```bash
docpipe web scan --root . --pages pages.yaml --out artifacts/doc-tree.web.json
docpipe web scan --root . --pages pages.yaml --fail-on-stale-overrides   # для CI
```

| Свойство | Как устроено |
|---|---|
| добавление | синтетическая запись маршрута с `source: pages.yaml`; дальше работает всё существующее, включая якорь бизнес-документа |
| снятие | отменяет **вид**, а не узел: класс остаётся компонентом и документируется как компонент, маршрут сохраняется как факт |
| порядок | автоматика → `add` → `remove`; снятие сильнее, это последнее слово человека |
| `reason` | обязателен: «сняли 12 страниц» без причин — снова безымянное число |
| протухшее правило | печатается всегда, роняет прогон только с `--fail-on-stale-overrides` |
| неоднозначное снятие | отказ с перечислением: компонент на двух маршрутах снимается целиком |

## Документ страницы — агрегат

Узел, до которого дотягивается **ровно одна** страница, своего документа
не получает: он описывается внутри неё. Узел, до которого дотягиваются две
и больше, остаётся самостоятельным документом и попадает в страницу ссылкой.

Порога нет: «общий» — это «появился второй потребитель», а не «потребителей
больше N».

Разделы генерируемого блока у страницы:

| Раздел | Что в нём |
|---|---|
| Маршрут страницы | маршруты и их состояние |
| Дочерние страницы | ссылки на документы страниц, лежащих ниже по дереву маршрутов |
| Состояние | стейты, их имена из `@State` и члены, которые зовут |
| Что зовёт страница | узлы, до чьих членов страница доходит, и где каждый описан |
| Данные | эндпоинты с путём и экшеном |
| Состав документа | поглощённые узлы; общие — списком ссылок |

Автор пишет: «Зачем эта страница», «Что на экране», «Состояние», «Логика»,
«Откуда данные», «Что можно сделать», «Замечания».

### Хэши

`impl_hash` страницы включает хэши поглощённых узлов, `signature_hash` — их
состав. Правка сервиса, живущего внутри страницы, помечает её документ
устаревшим; переезд узла в страницу или из неё — тоже, даже если код не менялся.

### Что стало с документами поглощённых узлов

Они не удаляются и не переписываются. `docs status` называет их сиротами
с причиной «описывается внутри страницы X», а `docs adopt` отказывается
и говорит, в какие разделы перенести текст. Удаление — команда человека.

```bash
docpipe docs status artifacts/doc-tree.web.json --root .
```

## Где лежат документы фронта

Отдельной веткой дерева — ключ `web.modules_dir`, каталог внутри `docs_root`
рядом с `modules_dir`:

```
docs/modules/...   бэкенд, единица документации — класс
docs/front/...     фронт,  единица документации — страница
```

Пустое значение — та же ветка, что у бэкенда (умолчание, ради совместимости).
Смена значения меняет пути всех узлов фронта: прогон откажется, пока манифест
не пересобран, а после `web scan` документы переедут сами и получат отметку
о пересмотре.

## Состояние решения `page_covered`

Поглощённый узел — принятое решение, а не пробел. В отчёте настройки он идёт
отдельной строкой и не растит `undecided`:

```bash
docpipe web scan --root . --stats
docpipe symbols --root . --lang ts --state page_covered
```

## Бизнес-слой

Якорь `page` пишется на маршрут. В его фактах — маршрут, списки реестра,
эндпоинты и имена стейтов (`innerDebt`, а не `DebtState`). Ни одного имени
класса: переименование класса `business_hash` не меняет, смена имени стейта
или состава эндпоинтов — меняет.

## Порядок настройки на новом репозитории

1. `docpipe web scan --root . --stats` — довести `undecided` до нуля;
2. `docpipe web pages …` — посмотреть список страниц и обоснования;
3. завести `pages.yaml`: снять layout-обёртки, добавить экраны, которых нет
   в таблице роутов;
4. `docpipe web pages … --format csv` — разметить страницы глазами;
5. `docpipe materialize` — создать документы;
6. `docpipe docs status` — увидеть сирот и перенести из них текст.
