# docpipe в репозитории АС CF

Поставка инструмента построения дерева документации. Это **не** копия
репозитория разработки: здесь только пакет, его зависимости и настройка под
проект. Тестов, фикстур, плана, журнала, `ruff` и `mypy` здесь нет и быть
не должно.

```
docs/ml/docspipe/
├── docpipe/              пакет
├── pyproject.toml        только runtime-зависимости (5 штук)
├── uv.lock               зафиксированные версии, 17 пакетов
├── uv.toml               настройки uv: зеркало пакетов, сертификаты (см. ниже)
└── cashflow-docspipe/    всё, что настроено под АС CF
    ├── docpipe.yaml      что документируем, куда не заходим, куда пишем
    ├── rules.yaml        правила классификации под АС CF
    ├── ownership.yaml    кому принадлежит документ; приезжает заготовкой
    ├── templates/        скелеты документов шага 2 и заполненные образцы
    ├── artifacts/        манифест (создаётся при прогоне)
    └── .cache/           кэш разбора (создаётся при прогоне)
```

Шаблоны лежат в `cashflow-docspipe/`, а не рядом с пакетом, потому что скелет
документа — настройка под проект в той же мере, что и `rules.yaml`. Путь к ним
прописан в `docpipe.yaml` явно и убирать его нельзя: значение `templates`
по умолчанию отсчитывается от **текущего каталога**, а команды зовутся из корня
репозитория АС CF. Вторая ступень поиска — каталог самого `docpipe.yaml` —
сделала бы и короткое `templates` рабочим, но явный путь надёжнее и остаётся.

## Установка на закрытом контуре

Это основной сценарий: пакеты приходят из внутреннего зеркала, а не с pypi.org.

```bash
cd $WORK/docspipe/documentation_pipeline
./deploy/install.sh $WORK/cfml/sbt.cms.cashflow \
    --index https://зеркало/repository/pypi/simple \
    --python 3.12.13
```

**`--index` обязателен, и он делает больше, чем прописывает адрес.** Лок в
поставке собран против pypi.org и ссылается на файлы поимённо — с ним uv никуда
больше не пойдёт, сколько зеркал ни настраивай. Поэтому `--index` **пересобирает
лок** против указанного зеркала. Лок при этом не удаляется: uv предпочтёт уже
записанные версии, если зеркало их отдаёт, и окружение совпадёт с тем, на котором
гонялись тесты.

Адрес записывается в `uv.toml` рядом с пакетом, и дальше действует сам — на
`uv lock`, `uv sync` и `uv run`, из какого бы каталога их ни звали. Помнить
переменные окружения не нужно; при следующей установке файл сохраняется.

Флаги, которые обычно нужны там же:

| Флаг | Когда |
|---|---|
| `--python 3.12.13` | доступна одна конкретная сборка Python. Скачивать интерпретатор запрещено (`python-downloads = "never"` в `uv.toml`), поэтому его надо назвать |
| `--no-install-project` | зеркало не отдаёт `hatchling`. Тогда сам пакет не собирается, ставятся только 5 зависимостей, а команда зовётся только как `python -m docpipe` с `PYTHONPATH` на каталог инструмента |
| `--relock` | адрес зеркала уже прописан глобально в `~/.config/uv/uv.toml`, задавать его тут незачем — но лок всё равно надо пересобрать |

### `invalid peer certificate`

TLS-прокси компании подписывает соединения сертификатом внутреннего
удостоверяющего центра, которого нет в наборе, вшитом в uv. В `uv.toml` поставки
для этого стоит `native-tls = true` — использовать системное хранилище. Если
корневого сертификата нет и там, укажите его явно:

```bash
SSL_CERT_FILE=/путь/до/corp-root-ca.pem ./deploy/install.sh <репозиторий> --index …
```

Свежий uv на строку `native-tls` ругается: «deprecated, use `system-certs`».
Настройка при этом работает. Переименовывать её можно, только зная версию uv на
машине: неизвестный ключ uv.toml не игнорирует, а падает с ошибкой разбора.

### Если зеркало отдаёт не всё

Часть пакетов может быть недоступна и через зеркало. Тогда окружение подбирается
один раз руками внутри контура, а результат — `pyproject.toml`, `uv.lock`,
`uv.toml` — возвращается в клон, и дальше установка идёт уже без подбора.
Пошагово: [`OFFLINE.md`](OFFLINE.md).

### Обычная машина с доступом к pypi.org

```bash
./deploy/install.sh $WORK/cfml/sbt.cms.cashflow
```

Лок из поставки используется как есть, ничего пересобирать не нужно.

## Обновление

Тот же `install.sh` поверх установленного. Что он **не** трогает:

- настроенные `docpipe.yaml`, `rules.yaml`, `ownership.yaml`, `uv.toml`
  и правленые шаблоны из `cashflow-docspipe/templates/` — новые версии кладутся
  рядом как `*.new`;
- лок, пересобранный против внутреннего зеркала. Затереть его локом из поставки
  значило бы отправить следующий `uv sync` на недоступный pypi.org, поэтому
  вместо копирования он пересобирается против того же зеркала.

## Запуск

Переменные задаются один раз в сессии:

```bash
export CF_ROOT=$WORK/cfml/sbt.cms.cashflow
export DOCPIPE=$CF_ROOT/docs/ml/docspipe
export BUNDLE=$DOCPIPE/cashflow-docspipe
export PYTHONPATH=$DOCPIPE
export OUT=$BUNDLE/artifacts/doc-tree.json

alias docpipe="uv run --no-sync --project $DOCPIPE python -m docpipe"
```

```bash
cd $CF_ROOT     # `out` в конфигурации задан относительно текущего каталога

docpipe scan --root . --config $BUNDLE/docpipe.yaml --stats     # состояние решений
docpipe symbols --root . --config $BUNDLE/docpipe.yaml          # что осталось без решения
docpipe scan --root . --config $BUNDLE/docpipe.yaml --jobs 4    # построить манифест
docpipe validate $OUT                                           # проверить построенное
```

**`--no-sync` обязателен:** без него `uv run` при каждом вызове сверяется с индексом
и на машине без доступа к нему падает — на команде, которая с зависимостями ничего
не делает. Окружение поднимает `install.sh`, и это его работа.

**`python -m docpipe`, а не консольная команда `docpipe`:** работает и когда пакет
собран, и когда окружение поднято с `--no-install-project`. `PYTHONPATH` нужен
для второго случая — пакет лежит в дереве, но не в `site-packages`.

Всё остальное — в [`cashflow-docspipe/README.md`](cashflow-docspipe/README.md).

## Без алиаса, одной строкой

```bash
cd $WORK/cfml/sbt.cms.cashflow
BUNDLE=docs/ml/docspipe
PYTHONPATH=$BUNDLE uv run --no-sync --project $BUNDLE python -m docpipe scan \
    --root . \
    --config $BUNDLE/cashflow-docspipe/docpipe.yaml \
    --rules  $BUNDLE/cashflow-docspipe/rules.yaml \
    --jobs 4
```

`python -m docpipe` вместо консольной команды `docpipe` — работает и когда пакет
установлен, и когда окружение поднято как `--no-install-project`. `PYTHONPATH`
нужен для второго случая: пакет лежит в дереве, но не в `site-packages`.
