# Сборка окружения внутри закрытого контура

Когда это нужно: `install.sh --index` не проходит, потому что часть пакетов зеркало
не отдаёт вовсе. Тогда окружение подбирается **один раз руками** внутри контура,
результат фиксируется тремя файлами (`pyproject.toml`, `uv.lock`, `uv.toml`), и
дальше установка на любую машину периметра идёт уже без подбора.

Если `install.sh --index` отработал — этот документ не нужен, см.
[`README.md`](README.md).

## Что понадобится

- `uv` в `PATH` (`uv --version`);
- интерпретатор Python 3.12 — в целевой системе это `cpython-3.12.13`;
- адрес внутреннего зеркала пакетов;
- корневой сертификат компании, если системное хранилище его не содержит.

Переменные, которые используются дальше. `$WORK` (`/home/work/<логин>`) в целевой
системе уже задана:

```bash
CLONE=$WORK/docspipe/documentation_pipeline
CF=$WORK/cfml/sbt.cms.cashflow
BUNDLE=$CF/docs/ml/docspipe
```

---

## Шаг 1. Склонировать репозиторий

```bash
mkdir -p $WORK/docspipe
cd $WORK/docspipe
git clone <адрес репозитория> documentation_pipeline
```

Ничего собирать здесь не нужно: `install.sh` работает с исходниками напрямую,
окружение разработки на целевой машине не поднимается никогда.

## Шаг 2. Разложить поставку, не трогая сеть

```bash
cd $CLONE
./deploy/install.sh $CF --skip-sync
```

Файлы на месте, ни одного обращения к индексу пакетов не было.

**Почему подбор идёт здесь, а не в `deploy/`.** `uv lock` собирает метаданные
самого пакета, а `deploy/pyproject.toml` объявляет `packages = ["docpipe"]` —
рядом с ним пакета нет, и команда упадёт раньше, чем дойдёт до зависимостей.
В `$BUNDLE` лежит и то и другое, и это ровно тот каталог, где инструмент потом
будет работать: подбираем там, где проверяем.

## Шаг 3. Настроить uv

```bash
cd $BUNDLE
cp uv.toml.example uv.toml
```

Вписать адрес зеркала в `[[index]].url`. Остальное в шаблоне уже готово:
`native-tls = true` (системное хранилище сертификатов) и
`python-downloads = "never"` (не ходить за интерпретатором на github.com).

Если корневого сертификата нет и в системном хранилище — он задаётся переменной
окружения, в `uv.toml` для этого места нет:

```bash
export SSL_CERT_FILE=/путь/до/corp-root-ca.pem
```

Проверка, что зеркало отвечает и сертификат принимается, — до всякого подбора.
Отдельный пустой проект, чтобы не трогать поставку:

```bash
mkdir -p /tmp/probe && cd /tmp/probe
printf '[project]\nname="probe"\nversion="0"\nrequires-python=">=3.12"\ndependencies=["pyyaml"]\n[tool.uv]\npackage=false\n' > pyproject.toml
cp $BUNDLE/uv.toml .
uv lock --python 3.12.13
```

`Resolved 2 packages` — зеркало отвечает. `invalid peer certificate` — дело
в сертификате, а не в составе пакетов; чинить `SSL_CERT_FILE`, а не `pyproject.toml`.

## Шаг 4. Подобрать состав зависимостей

```bash
cd $BUNDLE
rm -f uv.lock                       # лок из поставки от pypi.org, для подбора он мешает
uv lock --python 3.12.13
```

Дальше цикл: читать ошибку → править `pyproject.toml` → повторять `uv lock`.

**Свобода по каждому пакету разная, и это важно.** Не все ограничения в
`pyproject.toml` — вкусовщина:

| Пакет | Зачем | Что можно менять |
|---|---|---|
| `tree-sitter>=0.25,<0.27` | разбор C# | **ниже 0.25 нельзя.** В 0.25 сменился API запросов (`Query(LANG, src)` + `QueryCursor(q).captures()`), на старом код не работает вовсе — это не стилистика |
| `tree-sitter-c-sharp>=0.23,<0.24` | грамматика C# | другая версия допустима, но её номер попадает в манифест и в ключ кэша: вывод может измениться, кэш обнулится. Золотой файл в репозитории собран на этой |
| `pydantic>=2.7,<3` | модели данных | любая 2.x посвежее; на 1.x код не работает |
| `typer>=0.12,<1` | командная строка | тянет `click`, `rich`, `shellingham`. Версия почти безразлична |
| `pyyaml>=6,<7` | конфигурация и правила | 6.x; 5.x, скорее всего, заработает, но не проверялось |

Что делать с типовыми отказами:

| Ошибка | Что это значит | Как чинить |
|---|---|---|
| `no versions available` для пакета | зеркало его не проксирует вовсе | шаг 5 |
| диапазон не удовлетворяется | зеркало отдаёт только старые версии | ослабить границы по таблице выше; `tree-sitter` — не ниже 0.25 |
| качается `.tar.gz` вместо `.whl`, сборка падает | зеркало отдаёт только исходники, а `tree-sitter` и `tree-sitter-c-sharp` — расширения на C | нужен компилятор и заголовки Python: `gcc`, `python3.12-devel`. Если их нет — тоже шаг 5 |
| нет `hatchling` | это сборочный бэкенд самого `docpipe` | не чинить: ставить с `--no-install-project`, см. шаг 6 |

Правки в `pyproject.toml` делать **в `$BUNDLE`**, а не в клоне: обратно они уедут
на шаге 7, когда станет понятно, что набор рабочий.

## Шаг 5. Если пакета нет вовсе: принести колёса

На машине, у которой доступ есть, выгрузить весь набор:

```bash
uv export --no-dev --no-emit-project --format requirements-txt > requirements.txt
pip download -d wheels -r requirements.txt \
    --only-binary=:all: --python-version 3.12 --platform manylinux2014_x86_64
```

Каталог `wheels` перенести внутрь контура и указать его в `uv.toml`:

```toml
find-links = ["/абсолютный/путь/до/wheels"]
offline = true
```

`offline = true` запрещает любой сетевой доступ: uv соберёт окружение только из
принесённых файлов. Это же и проверка — если чего-то не хватает, вы узнаете об
этом сразу и по имени пакета, а не по таймауту.

## Шаг 6. Поднять и проверить

```bash
cd $BUNDLE
uv sync --frozen --python 3.12.13
```

Если `hatchling` недоступен — тот же вызов с `--no-install-project`: встанут только
пять зависимостей, сам пакет собираться не будет. На то, как инструмент вызывается,
это не влияет: `run.sh` работает в обоих режимах.

Проверка по возрастанию требовательности — важна именно последняя, она поднимает
разбор, грамматику, модели и YAML разом:

```bash
PYTHONPATH=$BUNDLE uv run --no-sync --project $BUNDLE python -m docpipe version
cd $BUNDLE/cashflow-docspipe
./run.sh -- schema --out /tmp/schema.json      # pydantic жив
./run.sh stats                                 # весь конвейер, ничего не пишет
```

## Шаг 7. Зафиксировать результат в клоне

```bash
cp $BUNDLE/pyproject.toml $CLONE/deploy/pyproject.toml
cp $BUNDLE/uv.lock        $CLONE/deploy/uv.lock
cp $BUNDLE/uv.toml        $CLONE/deploy/uv.toml
```

После этого установка на любую другую машину периметра — одна команда без всяких
флагов: адрес зеркала берётся из `deploy/uv.toml`, версии — из `deploy/uv.lock`,
который теперь тоже собран против зеркала.

```bash
cd $CLONE
./deploy/install.sh <другой репозиторий>
```

**Про внешний remote.** `uv.toml` и пересобранный `uv.lock` содержат адрес
внутреннего зеркала. `deploy/uv.toml` в `.gitignore` — он остаётся локальным
и переживает `git pull`. С `deploy/uv.lock` решать вам: коммит внутри контура
полезен (следующий человек не повторяет подбор), но пушить его на внешний remote
значит вынести туда внутренний адрес.

## Что будет при следующем обновлении инструмента

`install.sh` поверх такой установки:

- **не тронет** `uv.lock`, собранный против зеркала, — иначе следующий
  `uv sync --frozen` ушёл бы на недоступный pypi.org;
- пересоберёт его, **только если изменился состав зависимостей** (сравнивается
  `pyproject.toml` поставки с установленным). Обновление одного кода связи
  с зеркалом не требует;
- сохранит настроенные `docpipe.yaml`, `rules.yaml` и `uv.toml`, положив новые
  версии рядом как `*.new`.

Если нужно обновить только код и ничего не собирать — `--skip-sync`.
