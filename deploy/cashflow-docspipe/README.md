# Настройка docpipe под АС CF

Всё, что относится к этому проекту, лежит в этом каталоге: `docpipe.yaml`
(где искать код), `rules.yaml` (что считать сервисом, контроллером, задачей
кластера) и `run.sh` (запуск). Сам инструмент — уровнем выше и правке
не подлежит: его обновляет `install.sh`.

Полный чек-лист настройки — в `CASHFLOW.md` репозитория разработки.

## Команды

```bash
./run.sh stats            # срезы для настройки правил, ничего не пишет
./run.sh scan             # построить манифест
./run.sh dry-run          # что изменилось бы, не записывая
./run.sh validate         # проверить построенное
./run.sh diff старый.json # сравнить с другим манифестом
./run.sh -- version       # что угодно ещё, напрямую в docpipe
```

Переменные окружения: `JOBS` (по умолчанию 4), `OUT` (путь манифеста),
`CF_ROOT` (корень репозитория, если раскладка отличается от описанной).

Результат прогона:

```
artifacts/doc-tree.json       манифест — детерминированный, вход для шага 3
artifacts/doc-tree.run.json   сидкар: время, хост, счётчики, битые файлы
```

Всё недетерминированное — только в сидкаре. Два прогона подряд обязаны дать
побайтово одинаковый `doc-tree.json`; если это не так — это дефект, а не
особенность.

## Порядок первичной настройки

**1. Уточнить `enrolled` в `docpipe.yaml`.** Сейчас там `src/**` вслепую.
В репозитории 491 проект — посмотреть, как они разложены:

```bash
cd "$(git rev-parse --show-toplevel)"
find . -name '*.csproj' -printf '%h\n' | cut -d/ -f2 | sort | uniq -c | sort -rn
```

**2. Прогнать `./run.sh stats`** и посмотреть пять срезов: окончания имён,
базовые типы, атрибуты, модули, namespace-ы.

**3. Взять самое частое из непокрытого, дописать одно правило, повторить.**
Правило, покрывающее 500 типов, полезнее пяти правил по десять. Останавливаться,
когда `unclassified` перестанет заметно падать.

**4. Проверить спорные типы** — почему победило не то правило, которое ожидалось:

```bash
jq '.nodes[] | select(.title=="…") | {kind, matched_rules}' artifacts/doc-tree.json
```

## Что проверить именно на этом репозитории

Диагностика уже выполнена, ответы разобраны в `CASHFLOW.md` §1. Открытыми
остались четыре вопроса — все они помечены в `rules.yaml` и `docpipe.yaml`
как «требует проверки».

**Ignite / GridGain.** Правила `ignite.*` написаны по Apache Ignite; в АС CF
используется GridGain, и namespace-ы могут отличаться. Команды для проверки —
в комментарии перед правилом `ignite.service`.

**Каталоги с «Test» в имени.** Шаблоны исключения сужены до `*.Test(s)/`,
чтобы не потерять предметные `StressTest`, `BackTest`. Проверить, что при этом
не остались невыключенными настоящие тестовые каталоги:

```bash
cd "$(git rev-parse --show-toplevel)"
find . -type d \( -name '*Test' -o -name '*Tests' \) -not -path '*/obj/*' | grep -v '\.Tests\?$'
```

**Файлы, потерянные при разборе.** Директива `#if` внутри выражения уничтожает
объявление типа целиком, и снаружи это ничем не видно, кроме сидкара:

```bash
jq '.parse_error_files' artifacts/doc-tree.run.json
```

В АС CF таких файлов немного (13 с условной компиляцией на 17988), но список
нужно просмотреть глазами: если среди потерянных есть важные типы, лечение
одно — вынести `#if` за пределы выражения в исходнике.

**Связанные исходники.** Один `.csproj` подключает файлы через
`<Compile Include>`. Такой файл лежит вне каталога проекта и в индекс не
попадает вовсе. Посмотреть, что именно теряется:

```bash
cd "$(git rev-parse --show-toplevel)"
grep -rl "Compile Include" --include=*.csproj .
```

## Почему `docs/**` исключён

В `docpipe.yaml` есть `exclude: ["docs/**"]`, и убирать это нельзя: сам
инструмент лежит внутри сканируемого репозитория (`docs/ml/docspipe`) вместе
с окружением `.venv`. Без исключения обход заходил бы в тысячи чужих файлов,
а когда добавится разбор `.py`, docpipe принялся бы документировать сам себя.

Шаблон обязан заканчиваться на `/**`. Без этого он совпадёт только с самим
каталогом, но не с файлами под ним, — и будет выглядеть работающим.
